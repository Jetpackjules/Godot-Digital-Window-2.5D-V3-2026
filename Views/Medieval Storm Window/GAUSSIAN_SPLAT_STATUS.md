# Gaussian Splat Status

This note records the current state of the Medieval Storm Window landscape
implementation as of July 2026. It distinguishes intended behavior from what
has actually been observed in the Godot editor and in a running build.

## What Was Added

- Three selectable CC BY 4.0 SuperSplat landscapes:
  - Cochem Imperial Castle: https://superspl.at/scene/9b18007e
  - Sumela Monastery Cliffside: https://superspl.at/scene/5f03cdcb
  - Sovinec Castle: https://superspl.at/scene/0f5e0540
- Each landscape has an authored `Node3D` placement under
  `GaussianLandscapeAnchor`. Its transform is saved in `View.tscn`, so it can
  be positioned in the editor and is not regenerated by the scene script.
- The source `.sog` files contain roughly 2 million splats each. The project
  also has generated editor previews containing roughly 120,000 splats each.
- GDGS (Godot Gaussian Splatting) provides the native Gaussian compositor.

## Current Behavior

| Context | Point Proxy (Safest) | Gaussian Splats (Native LOD) |
| --- | --- | --- |
| Normal 3D editor viewport | Visible and directly editable | Not drawn |
| Camera Inspector preview | Not the intended workflow | Visible |
| Running scene / runtime | Not visible by design | Intended to be visible, but currently does not appear in the observed runtime path |

### Why The Modes Behave Differently

`Point Proxy (Safest)` is a standard Godot mesh built from colored points. It
is deliberately editor-only: it is fast enough for positioning and gives a
useful composition proxy, but it is not a Gaussian-splat renderer and is not
used in a build.

`Gaussian Splats (Native LOD)` uses the GDGS compositor. Godot's normal 3D
editor viewport does not run that compositor effect, so the splat is absent
there. The Camera Inspector preview does run it, which is why the Gaussian is
visible only in that panel. This is a renderer/editor integration limitation,
not a visibility toggle the user has missed.

## Known Problems

1. **Runtime visibility is currently broken or unverified.** The native
   Gaussian renderer is supposed to use the selected full `.sog` resource at
   runtime. In the observed scene launches, neither the editor point proxy nor
   the Gaussian landscape was visible. The proxy absence is expected; the
   Gaussian absence is the outstanding bug.
2. **The Camera Inspector Gaussian looks low-resolution.** It uses the
   approximately 120,000-splat editor LOD, not the approximately 2-million
   splat source. It is meant for placement confirmation rather than final
   image-quality evaluation. It can also look soft because the renderer blends
   ellipses, unlike the crisp point proxy.
3. **Native Gaussian editor preview is not suitable for direct viewport
   authoring.** It only appears through Camera Inspector preview and can become
   expensive when the editor camera gets close to the landscape.
4. **Do not judge final visual quality from the point proxy.** The proxy can
   look sharper because it renders discrete colored points, but it does not
   reproduce Gaussian opacity, anisotropic footprint, or view-dependent
   blending.

## Practical Workflow Today

1. Use `Point Proxy (Safest)` to choose a landscape and author its transform in
   the main 3D editor viewport.
2. Switch to `Gaussian Splats (Native LOD)` and select `Camera3D` to inspect
   the native compositor output in the Camera Inspector.
3. Treat the native editor preview as a low-resolution composition check only.
4. Before using this view as a main/projector experience, resolve the native
   runtime visibility failure and validate it in a direct non-iPhone scene
   launch.

## Next Debugging Target

Trace the selected `GaussianSplat` node through a direct runtime launch of
`Views/Medieval Storm Window/View.tscn`: confirm that its source `.sog` is
loaded, its compositor effect is registered on the active viewport, and its
render contribution is not discarded by the active camera, cull mask, or
runtime compositor settings. Do this before tuning resolution or adding more
landscapes.
